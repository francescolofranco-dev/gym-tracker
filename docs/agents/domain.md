# Domain docs

This repository uses a single context: `GLOSSARY.md` at the repository root and architecture decision records in `docs/adr/`.

Before exploring the codebase, read the glossary and ADRs relevant to the area being changed. If they do not exist, proceed silently. The domain-modeling skill creates them lazily when terms or decisions are resolved.

Use glossary terms when naming domain concepts in issues, code, tests, and proposals. If a term is missing, reconsider whether it belongs to the domain or record the gap for domain modeling.

If a proposal contradicts an existing ADR, identify the ADR and explain why its decision should be revisited.
